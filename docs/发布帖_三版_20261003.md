## 版本 A · Show HN（英文）

**Title:**
`Show HN: Flowing Memory – a local-first AI memory system with zero embedding APIs`

**Body:**

Most AI memory systems today work the same way: store memories as rows, then at query time
embed the question, do a vector search, and stuff the top-K into the context window.

I took the other road.

**Flowing Memory** is a memory system where memories don't get *retrieved* — they get *disturbed*.

- Every memory has a **heat** that decays over time (λ=0.10/day) and spikes when it's touched.
- Memories are linked in a weighted concept graph, so one hit ripples out to a whole neighborhood.
- **Nothing is ever deleted.** Memories cool down, get marked outdated, or get skeletonized — the original text stays.

The whole thing is **pure Python standard library + SQLite (FTS5)**. No embedding API. No LLM calls.
No network. Your memories never leave your disk.

**Honest numbers** (all reproducible, all annotated with test conditions):

| | |
|---|---|
| Scale tested | 4,471 memories · 19 tables · 56.3 MB · 6,888 graph nodes / 34,845 edges |
| Exact-hit recall | **0.09 s** |
| Associative recall (multi-hop) | **0.47 s** |
| **Chinese recall (structure-based)** | **96.7%** — on a self-built set, *not* a standard benchmark |
| **English recall** | **27–32%** — ⚠️ **a real weakness** (no vector layer, that's the price of zero dependencies) |

I'm not going to pretend the English number is fine. It's the honest cost of the design:
structure-based recall works great for Chinese, and literal matching is all you get for English.

What I'd genuinely like feedback on: **is the "flow" model actually better for long-term memory,
or is it just a prettier metaphor for the same thing?**

Repo: https://github.com/sunquan81/FlowMemory

## 版本 B · Reddit r/LocalLLaMA（英文·口语版）

**Title:**
`I built a memory system that runs 100% local with zero dependencies – no embedding API, no LLM calls`

**Body:**

Tired of every "AI memory" library phoning home to an embedding API, I built one that doesn't.

**What it is:** a local-first memory system in pure Python stdlib + SQLite. Nothing to `pip install`.

**How it's different by design:**
- Memories have **heat** — they cool over time, heat up when used, and **never get deleted**.
- Recall is a **concept graph ripple**, not a top-K vector search.
- Written results come back with an **audit ledger** (which memory got confirmed, which got corrected).

**Real numbers from my own use** (4,471 memories):
- exact hit: 0.09 s · multi-hop associative: 0.47 s
- Chinese: **96.7%** (self-built set, not a standard benchmark — I'll say that up front)
- English: **27–32%** ← this is the weak spot, no vector layer by design

**Why I'm posting:** I want to know if other people hitting the same wall — "my agent forgets everything
and every memory lib wants my data in someone's cloud" — find this useful, or if the honest answer is
"just use a vector DB and stop being clever."

Repo: https://github.com/sunquan81/FlowMemory
