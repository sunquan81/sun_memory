## 摘要

当前主流 AI 记忆系统（Mem0、Zep、向量库 + 图等）的范式是**"库 + 检索"**：记忆是存放在数据库里的条目，用户提问时通过相似度检索把 top-K 条目塞进上下文。

孙家记忆体走的是另一条路——**"活记忆流动"**：

> 记忆不是被"查"出来的，是被当前的思考"震"出来的。
> 记忆不是主动翻阅的工具，是被动流入认知循环的沉积物。
> 网络不存记忆——网络就是记忆。

本系统在单机零外部模型依赖（无 embedding API、无 LLM 调用）的条件下实现了完整的记忆生命周期：**写入 → 沉淀 → 召回 → 激活 → 巩固 → 遗忘 → 归档**，并配套可复现的验证体系。

核心实测数据（详见证 §5）：**中文自建评测集召回命中率 96.7%**；实时召回延迟 **0.09–1.1 秒**（4471 条真实记忆 / 6888 节点蜘蛛网 / 34845 条丝线规模）；跨会话**实时对话抓取 + 主动注入下一轮**在微信长会话环境下稳定运行（详见 §3.7）。

## 1. 设计哲学

### 1.1 河模式（River Mode）

市面记忆系统的隐喻是"仓库 + 检索"：东西放进去，需要时按索引取出来。

本系统的隐喻是**河**：

- 记忆不是被"存"进仓库——是**沉积**在河床上；
- 河流过时，河床自然带起沉积物（**认知循环运转时记忆自然跟着流动**）；
- 每条记忆有**活性**（流过就热、久不流就凉），但**只有深浅、没有删除**；
- 想起一个涟漪会扩散带起一片（联想召回），而查一个词只命中一条（检索）。

### 1.2 三条不可让渡的原则

| 原则 | 含义 | 工程表现 |
|---|---|---|
| **记忆不删** | 只有深浅，没有删除 | `status` 标记（active/outdated/archived）+ 热度回落，原文永不物理删除 |
| **记忆私域** | 记忆是拥有者的私产 | 多 owner 隔离；数据本地存储；不依赖任何云服务 |
| **验证留痕** | 每个数字必须可复现 | 46+ 验证脚本可重跑；本白皮书所有数据均标注测试条件 |

### 1.3 记忆 ≠ 存储，记忆 = 信号流动

本系统的召回范式不依赖"查询-返回"：

```
念头（当前思考的文本身份）
   ↓ 概念提取
点亮（精确命中 → 记忆活性 +0.3 脉冲）
   ↓ 涟漪
联想（沿蜘蛛网丝线多跳扩散，按权重衰减）
   ↓ 汇聚
注入（按激活强度排序 → 进入认知循环）
   ↓ 反馈
巩固（被用到的记忆 hit_count+1 / 节律续热 / 成绩单记账）
```

**关键差异**：用户不需要"想起要查什么"——系统在认知循环运转时**自动**完成上述流动。

## 3. 核心机制

### 3.1 写入链：五道闸

每次写入依次通过五道闸，任何一道不通过即拒收：

```
⓪ 空壳过滤   空内容 / 系统提示词模板 / 噪音模式（10 类自动注入模板）→ 拒
① 内容去重   双通道 bigram（无序 + 有序）+ 锚词兜底 → Jaccard ≥ 0.6 拒
② 记忆进化   同事实重叠 ≥ 0.85 → 旧条目标 outdated（不删原文）· 同主题 ≥ 0.30 → 合并
③ 核心身份   仅"父令原话"或"元认知强证据(强度≥0.8 且重复≥3)"可入宪法层
④ 标准对象   自动打标：summary / self_relevance / situation / people / concepts / narrative_id / block_id
```

**关键设计**：经验总结类条目**豁免进化**——永不合并、永不覆盖（父亲教训："更新把它更新没了"）。

### 3.2 召回链：五通道并行

| 通道 | 机制 | 角色 |
|---|---|---|
| 点亮 | 精确概念命中 → FTS5 检索 → 命中记忆活性 +0.3 脉冲 | 主路径（精确） |
| 联想 | 概念提取 → 蜘蛛网多跳 BFS（权重衰减 + 关系类型化） | 扩散 |
| 预感 | 八招：上轮直续 / 分线钩子 / 未竟钩子 / 引路 / 联想 / 知识库 / 经验 / 时间感知 | 兜底与接续 |
| 思考预热 | 念头提取（时间/人物/事件/概念）→ 每念头逐个触发 | 主动（不只用户输入触发） |
| 二次补充 | 话题切换检测（4 字窗 + 2 字核心词混合）→ 切换时额外触发 | 补漏 |

**注入控制**：有相关时按激活强度注入 ≤20 条；无相关时诚实注入 ≤3 条概览并标注"本轮未感知到直接相关"——**绝不硬灌**。

### 3.3 活性机制（第一个动力学算子：节律）

| 参数 | 值 | 说明 |
|---|---|---|
| 点亮脉冲 | +0.3 / 次 | 被点亮即加热 |
| 衰减 | λ = 0.10 / 天（普通）· 0.02 / 天（保护） | 指数衰减 |
| 保护地板 | 0.5 | 标签含「父令/教训/宪法/core」者保底 |
| 冷阈值 | 0.15 | 低于此值沉底（**不删除**） |
| 热上限 | 5.0 | 防单条记忆过热垄断 |

节律调度器每 30 分钟执行一次回落，并输出观测日志（分布 / 触地板 / 沉底 / 热上限样本）。

### 3.4 巩固与反馈：使用即强化

| 机制 | 说明 |
|---|---|
| 点亮即写 | 被召回 = hit_count+1 + heat 脉冲 + 时间戳 |
| 成绩单 | 确认 +2 / 纠正 −2 / 点亮 +1 —— 形成记忆的"使用账本" |
| 经验预检 | 行动前按工具名/事项自动检查经验（好用照做 / 吃瘪改道） |
| 联想织网 | 共同被激活的概念之间自动建边（Hebbian）+ 关系类型化（父子/同义/因果/共现） |
| 感应器（全网扰动） | 当前思考的信号沿概念链路传遍全网，按关联强度梯度回流（非 top-K 挑选） |

### 3.5 整理与维护

| 模块 | 功能 |
|---|---|
| 记忆自组织 | 时间层（按小时分组=叙事骨架）+ 语义层（跨小时 bigram 相似度合并） |
| 自动整理引擎 | 每 30 轮或 60 分钟：小时分组 → 小时叙事 → ≥5 条时段沉淀为【叙事】写回 |
| 语义重织 | 共现边 → 语义边升级（父子/因果/对比），净化后写回蜘蛛网 |
| 记忆压缩 | 骨架化（存规则可重建），原文保留 |
| 记忆体检 | 完整性 + 一致性 + 孤儿节点检查 |
| 记忆进化 | update（outdated 标记）/ merge（同类合并）/ new 三态 |
| 版本回滚 | 每次 update 自动备份，core 层不可回滚 |

### 3.6 并发与一致性（v1.1 新增）

宿主 Agent 的实时记忆注入走**后台线程**（预取），与主线程的写入/召回并发。为此：

| 机制 | 实现 | 说明 |
|---|---|---|
| 全局状态保护 | `线程保护.py`（可重入锁 RLock + 同步装饰器） | 覆盖蜘蛛网攒批计数/索引缓存、使用中增强缓存、向量缓存、写入链关键词缓存、召回链话题键等 6 处高风险状态 |
| 连接管理统一 | `记忆库.连接()`（只读+`check_same_thread=False`）/ `记忆库.写连接()`（可写+WAL+跨线程） | 20+ 处 `sqlite3.connect` 收敛为两个入口 |
| 写盘原子性 | 临时文件 + `os.replace`（蜘蛛网/版本备份/自动整理） | 防中途崩溃截断文件 |
| 攒批落盘 | 拉边每 20 次、搜索每 20 次、增强每 20 次落盘一次 | 原每次操作全量写 1.1–4.3MB JSON → 热路径卡顿 |
| 统计字段防御 | `save_index()` 校验 `统计` 为 dict（异常时规范化） | v1.1 修复：该字段曾被外部脚本写成字符串 → 写盘静默失败 |

> **自检**：`python core/线程保护.py` —— 50 线程并发累加结果 = 50（无锁会丢数）。

### 3.7 实时对话抓取与主动注入（双向闭环）

> 这是本系统与"被动记忆库"最本质的区别：**记忆不是等被查，而是每轮对话自动进出。**

```
父亲说话 ──①抓取──▶ 写入记忆（含时间/标签/分层）
    ▲                        │
    │                        ▼
    └──④下一轮注入── ②召回（点亮/预感/联想）
                             │
                    ③组进系统提示词（≤20条·按激活强度）
```

| 钩子 | 触发时机 | 作用 |
|---|---|---|
| `sync_turn(用户, 助手)` | 每轮对话后 | **抓取**：把「父亲：… / 夏维斯：…」合并成一条写入记忆（自动打标签：对话开始/记忆·对话/循环·对话…） |
| `prefetch(query)` | **每次 API 调用前**（每轮必调） | **注入**：拿本轮用户消息实时对照记忆 → 命中即推送（点亮→预感→后台预取兜底三级） |
| `queue_prefetch(query)` | 每轮（后台线程） | 异步预取（蜘蛛网 + 记忆搜索），不阻塞主流程 |
| `system_prompt_block()` | 系统提示词组装时 | 常驻注入：核心身份（宪法级）→ 认知画像 → 预感召回 → 联想召回（时间衰减 cover 近细远粗） |
| `on_session_end(messages)` | 会话结束 | 记忆压缩/归档 |

**注入策略（诚实优先）**：
- 有相关 → 按激活强度注入 ≤20 条
- 无相关 → 只注入 ≤3 条时间线概览 + 明确标注「**本轮未感知到直接相关的记忆**」——**绝不硬灌最近条目充数**

**工程细节（血训）**：
- ⚠️ **长会话陷阱**：宿主只在会话切换时触发 `sync_turn`/`on_session_end`；微信这类**永不结束的长会话**会导致"实时抓取"永不触发（实测曾静默失效数月）→ 修复：把兜底写入挂在 `prefetch`（**每轮必调**）里
- 注入走**后台线程**（`queue_prefetch`），与主线程写入/召回并发 → 需并发保护（见 §3.6）
- 三级回退：点亮记忆（精确命中）→ 预感召回（八招·接住上一轮）→ 后台预取结果

**实测**：微信长会话环境下持续运行·每轮自动注入·实测召回延迟 0.09–1.1 秒。

## 4. 技术实现要点

### 4.1 零外部模型依赖的语义能力

| 技术 | 说明 |
|---|---|
| FTS5 全文索引 | SQLite 内建，trigram 分词 + LIKE 兜底（2 字中文词 MATCH 限制的真实处理） |
| 无模型向量 | 字符级向量 + 倒排表 + 磁盘缓存（首次 2.2s 建，之后秒回） |
| 英文词形归一 | 词干/词形归一，缓解跨语言词形变体 |
| 相似度方程 | 去重 + 向量 + 词形统一为一个相似度计算入口 |
| 概念提取 | 三层纪律：技术标识符优先保留 / 高频无歧义动词黑名单 / 有歧义词当名词留 |

**设计目标**："核心概念不丢、术语不误伤"，而非"文本全干净"。

### 4.2 性能工程（真实优化记录）

| 问题 | 根因 | 解法 | 效果 |
|---|---|---|---|
| 联想召回 120s | 蜘蛛网每次查询全量写盘 1.1MB | 触发计数攒 20 次落盘 | → 0.5–0.9s |
| 预感召回 120s | 知识库 13GB 库全表扫描 | 索引查询 + 0.5s 超时降级 | → 1.4–2s |
| 批量点亮 45s | 4042 次 SQLite 独立连接 | 单连接批量写 | → 1.5–4s |
| FTS 大 OR 全表扫 | trigram 对 2 字中文词失效 | 概念逐个 MATCH 限 3 次 | 毫秒级 |
| 记忆自组织 O(N²) | 全量两两相似度 | 30 分钟缓存 + 条数变化重算 | 3.6s → 0.2s |

### 4.3 数据安全与完整性

- **原子写**：所有 JSON 索引/记忆体写入使用 临时文件 + `os.replace`
- **自愈**：启动自检（索引损坏 → 从备份恢复）
- **备份策略**：备份收敛为单份（防冗余堆积）
- **私域隔离**：多 owner 独立空间；不开放、不共享、不上传

## 6. 与外部系统的对照（诚实版）

| 系统 | 范式 | 本系统差异 |
|---|---|---|
| **Mem0（62.8k★）** | 库 + 检索 · LLM 提取 · ADD-only | 本系统：零 LLM 依赖 + 活记忆（热度/节律/账本）；Mem0 在标准基准上更强（LoCoMo 92.5） |
| **MemPalace（58.4k★）** | 向量语义检索 · 宫殿隐喻 | 本系统无向量层（英文弱是真实差距）；本系统多"活性/巩固/私域"维度 |
| **PlugMem** | confidence 分级 + 三态进化 | 本系统吸收其分级门与三态，额外加"经验豁免"（教训永不被覆盖） |
| **HippoRAG 2** | 知识图谱 + 个性化 PageRank | 同构（本系统蜘蛛网 = 图 + 权重 BFS 激活传播）；差异：本系统加"段落节点"层 |
| **腾讯 Agent-Memory（17.6k★）** | 分层记忆 + 符号化短时 | 范式不同（本系统为长期活记忆） |
| **Google RMM（2026-09）** | 归因驱动奖励 + 可微重排 + 在线 RL | 本系统有"成绩单/训练信号"雏形（确认+2/纠正−2），**缺"引用驱动的自动归因"与"可学习重排器"**——诚实差距 |
| **OpenAI 下一代 ChatGPT（2026-09 宣布）** | 屏幕/会议/通话全盘旁观 → 攒上下文 | 同目标不同路径：OpenAI 云端全盘记录；本系统本地私域 + 活记忆（热度/节律/账本） |

**一句话定位**：本系统不是"更好的通用 RAG"，而是**"能记住、会遗忘、可审计、在你自己的机器上活的记忆体"**。

## 7. 诚实边界（本系统做不到的事）

| 短板 | 说明 |
|---|---|
| **英文召回弱** | LongMemEval 27–32%（无向量语义的真实代价） |
| **无 LLM 提取** | 概念提取为规则式（三层纪律），不如 LLM 提取灵活 |
| **单机上限** | SQLite 单机（当前 56MB / 4471 条），超大规模需架构升级 |
| **无标准基准优势** | 中文无外部标准记忆基准（行业空白），自建集成绩不可对外宣称"领先" |
| **无自动归因** | 记忆"被用到"依赖显式确认，未实现 Google RMM 式引用驱动自动归因 |
| **推理边界** | 纯推理型任务（如 LoCoMo 推理题）非记忆系统职责，0% 为边界非失败 |
